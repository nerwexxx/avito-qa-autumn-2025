# Задание 2.1. Тест-кейсы для API объявлений

## Позитивные проверки

**TC-01: Создание объявления с валидными данными**
- **Шаги:** Выполнить POST-запрос на `/api/1/item` с валидным телом запроса (name, price, sellerId, statistics).
- **Ожидаемый результат:** Статус 200/201. В ответе возвращается JSON с уникальным идентификатором `id` созданного объявления.

**TC-02: Получение объявления по существующему ID**
- **Шаги:** Выполнить GET-запрос на `/api/1/item/{id}`, используя `id`, полученный при создании объявления.
- **Ожидаемый результат:** Статус 200. Возвращается массив с объектом объявления, поля (name, price, sellerId) совпадают с отправленными.

**TC-03: Получение всех объявлений по sellerID**
- **Шаги:** Выполнить GET-запрос на `/api/1/{sellerId}/item`.
- **Ожидаемый результат:** Статус 200. Возвращается массив объявлений, принадлежащих указанному продавцу.

**TC-04: Получение статистики по ID объявления**
- **Шаги:** Выполнить GET-запрос на `/api/1/statistic/{id}`, используя `id` существующего объявления.
- **Ожидаемый результат:** Статус 200. Возвращается объект или массив со статистикой (contacts, likes, viewCount).

## Негативные проверки

**TC-05: Создание объявления без обязательного поля (name)**
- **Шаги:** Выполнить POST-запрос на `/api/1/item` с телом, в котором отсутствует поле `name`.
- **Ожидаемый результат:** Статус 400 (Bad Request). Объявление не создается.

**TC-06: Получение объявления по несуществующему ID**
- **Шаги:** Выполнить GET-запрос на `/api/1/item/{id}`, где `id` — случайный несуществующий UUID.
- **Ожидаемый результат:** Статус 404 (Not Found) или 400 (Bad Request).

**TC-07: Получение объявлений по несуществующему sellerID**
- **Шаги:** Выполнить GET-запрос на `/api/1/{sellerId}/item`, где `sellerId` — несуществующий номер.
- **Ожидаемый результат:** Статус 200 и пустой массив `[]` (если API так задумано) или 404.
